# Weather artwork components

Weather Frame assembles a scene from independent components instead of drawing
one monolithic image. This follows the same basic pattern as the AvianVisitors
bird cutouts: stable transparent assets are selected and composited at runtime.

There are two asset levels:

- `scenes/<environment>/<condition>.png`: full 1600×1200 watercolor scenes
  pre-generated through Gemini. These take priority when available.
- `mountains/<condition>/<name>.png`: lightweight transparent procedural
  components used by the no-API fallback renderer.

Full scenes are generated by `python3 -m weather_frame.generate_scenes`; see the
main Weather Frame README for safe selection and API-key usage.

## Mountain contract

```text
mountains/
├── sun/
│   ├── alpine.png
│   ├── massif.png
│   └── sawtooth.png
├── snow/
├── clouds/
├── melting_snow/
└── manifest.json
```

Every condition folder contains the same mountain names. Matching names must:

- use a 1600×420 transparent RGBA canvas;
- describe the same aligned ridge and baseline;
- extend opaque mountain pixels to the bottom edge;
- use only artwork that remains legible after Spectra-6 quantization.

The renderer chooses the mountain name from the date and location, then chooses
its condition independently:

- `sun`: clear or mainly clear;
- `clouds`: cloudy, fog, rain, or thunder;
- `snow`: snow with a high at or below 2°C;
- `melting_snow`: snow with a high above 2°C.

This naming contract allows generated components to be replaced with hand-drawn
transparent PNGs without code changes.

## Regenerating the starter set

From the repository root:

```bash
python3 -m weather_frame.generate_assets
```

The generator recreates all aligned variants and `manifest.json`. Generated
files are source assets and should be committed.
